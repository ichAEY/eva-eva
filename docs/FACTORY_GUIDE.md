# Выпуск сайтов из шаблона

Обычный ChatGPT перед любой сборкой сначала читает [`../START_HERE.md`](../START_HERE.md), затем [`../RULES.md`](../RULES.md). Входные данные самостоятельно собираются из переданных ссылок, чата и приложений по [`INPUT_CHECKLIST.md`](INPUT_CHECKLIST.md). `AGENTS.md` является дополнительной точкой входа для Codex.

Шаблон готовится к новому салону заменой данных и медиа. Утверждённые компоненты, разметку карточек услуг и стили менять не нужно.

## Единственный источник данных

Клиентские данные находятся в `site-data.js`. Один и тот же объект используется desktop- и mobile-версиями. **Для нового салона начните с `site-data.blank.js`**: скопируйте его поверх `site-data.js`, после чего заполните только реальные данные. Демонстрационные услуги нужны исключительно для проверки дизайна основного шаблона, никогда не переносите их клиентам. Перед выпуском обязательно установите:

```js
mode: 'production'
```

Заполняйте только языки, обязательные для страны:

```js
// Россия
country: 'RU',
locales: ['ru', 'en']

// Армения
country: 'AM',
locales: ['ru', 'en', 'hy']
```

Для `RU` запрещено добавлять HY «на всякий случай». Код также поддерживает `UZ → ru/en/uz` и `TJ → ru/en/tg`, но эти режимы используются только по прямому указанию пользователя.

## Порядок производства

1. Выполните исследование всех переданных источников по `START_HERE.md` и `INPUT_CHECKLIST.md`.
2. Одним сообщением запросите все недостающие обязательные данные и разрешение конфликтов; не заставляйте пользователя повторно заполнять форму.
3. После получения ответа скопируйте `site-data.blank.js` поверх `site-data.js`.
4. Определите страну и языки, затем заполните только подтверждённые факты.
5. Сохраните утверждённые универсальные `salon.heroDescription` и `salon.about` из `site-data.blank.js` без изменений.
6. Перенесите услуги в `services`: одна реальная услуга — один объект; варианты одной услуги остаются в `variants`.
7. Подключите медиа по `RULES.md`, запись и контакты — только по настоящим ссылкам.
8. Оставьте `team`, `reviews`, `portfolio` и `gallery` пустыми, если данных нет. Не заменяйте отсутствие данных демонстрационными сущностями.
9. Проверьте сайт локально на desktop и mobile, затем установите `mode: 'production'`.
10. Выполните все проверки из раздела «Проверка перед выпуском» и публикуйте только по прямому поручению.

Обязательные блоки для production:

- `salon` — название, тип, город, адрес, короткое и полное описание;
- `schedule` — часовой пояс и интервалы работы;
- `contacts` — хотя бы один реальный способ записи;
- `media` — логотип, главное изображение и фото для блока «О нас»;
- `categoryLabels`, `categoryOrder`, `services` — каталог услуг;
- `rating` — реальное значение либо `null` и количество оценок;
- `team`, `reviews`, `portfolio`, `gallery` — реальные массивы либо пустые массивы.

Пустые необязательные разделы автоматически скрываются. Не заполняйте их демонстрационными мастерами, отзывами или фотографиями.

## Карточка услуги

Один объект в `services` всегда создаёт одну карточку услуги на desktop и mobile. Существующую логику карточки не меняйте.

```js
{
  id: 'haircut',
  category: 'Волосы',
  title: {ru: 'Стрижка', en: 'Haircut'},
  price: '12 000 ֏',
  duration: '1 ч',
  description: {ru: 'Стрижка с консультацией.', en: 'Haircut with consultation.'},
  variants: []
}
```

Правила:

- `id` уникален и не меняется после публикации;
- `category` должна присутствовать и в `categoryLabels`, и в `categoryOrder`;
- `price`, `duration` и `description` можно оставить пустыми — карточка сохранит штатную механику записи;
- длинное описание автоматически получает «Подробнее» по утверждённой логике;
- диапазон цены записывается как `18 000–30 000 ֏`;
- варианты услуги задаются объектами `{label, duration, price}` в `variants`;
- нельзя копировать карточку вручную в `desktop.js` или `mobile.js`.

Зафиксированный контракт дизайна подробно описан в `docs/SERVICES_STYLE_LOCK_V1.md`. На мобильном устройстве запрещено переносить название категории услуг на вторую строку, уменьшать шрифт или внутренние отступы ради принудительного размещения: если полные названия не помещаются, используется горизонтальная прокрутка. Категории мобильной галереи находятся на однотонном фоне, а последняя вкладка карточки мастера полностью прокручивается в видимую область.

## Медиа и ссылки

Канонический контракт медиа находится в [`RULES.md`](../RULES.md). Для нового сайта:

- `logo.webp` → заставка и верхний бренд/логотип;
- `master.00000.webp` → главное мобильное изображение + «О салоне» + fallback для ПК;
- `masterpc.00000.webp` → главное изображение ПК; если отсутствует, используется `master.00000.webp`;
- `gallery.00000.webp`, `gallery.00001.webp` ... → единый набор для «Наши работы» и полной галереи;
- `favicon-source.png` → системная иконка TANEM, не клиентский логотип.

Локальные файлы кладите в клиентский репозиторий и указывайте безопасным относительным путём. Один и тот же файл галереи можно ссылочно использовать и в `media.portfolio`, и в нужной группе `media.gallery`; физические дубликаты не нужны.

Внешние изображения и ссылки используют `https://`. Не оставляйте `logo-placeholder.svg`, `media-placeholder.svg`, `#` вместо реальной ссылки или демонстрационные записи. Отзывы, если они используются, должны быть только с рейтингом `5`. Текст реального отзыва не переписывается ради красоты; перевод добавляется отдельно, если он требуется языковой конфигурацией сайта.

## Проверка перед выпуском

Из корня проекта запустите:

```bash
node tests/validate-site-data.cjs --production
node tests/check-factory-contract.cjs
node tests/check-template-regression.cjs
```

После push дождитесь всех проверок GitHub Actions:

- схема данных и блокираторы выпуска;
- неизменность утверждённой карточки услуг и CSS-каскада;
- сравнение с эталоном в Chromium и WebKit;
- production-сценарий на desktop, mobile и широком touch-устройстве.

Публиковать сайт можно только после зелёного результата всех проверок.

## Новый клиентский репозиторий

Создайте **пустой** GitHub-репозиторий без автоматически созданного README. Самый безопасный путь — клонировать утверждённую release-ветку шаблона с историей, а затем сменить адрес удалённого репозитория:

```bash
git clone --branch salons-v1-production --single-branch https://github.com/ichAEY/Shablon-only-for-salons.git CLIENT
cd CLIENT
cp site-data.blank.js site-data.js
# Заполните site-data.js и добавьте реальные изображения
# Затем поменяйте mode на production
node tests/validate-site-data.cjs --production
git remote set-url origin https://github.com/OWNER/NEW_CLIENT_REPO.git
git add site-data.js
git commit -m "Create salon from approved TANEM template"
git push -u origin salons-v1-production:main
```

В команде `git add` укажите также реальные фотографии, логотип и остальные новые файлы. Если скопировали файлы без истории, GitHub Actions автоматически получает контрольный коммит утверждённого шаблона из исходного репозитория.

**Проверка перед отправкой клиенту:** статус всех GitHub Actions зелёный; в продакшене реальные названия и фотографии на всех языках выбранной страны; услуги и цены на ПК/телефоне; связь и запись; отсутствующие разделы скрыты. В клиентском репозитории CI сравнивает исходную разметку услуг и CSS с эталоном, а браузер открывает уже заполненный сайт.

### Галерея и просмотр фотографии (мобильная/ПК)

Мобильная рамка ленты категорий берётся по мотивам Эсмеральды (14 px), но внешняя полоса остаётся точно в цвет основного фона галереи. Кнопки и названия категорий не сжимаются. Мобильная кнопка «Открыть галерею» в предпросмотре **из портфолио** и счётчик располагаются на одной линии ниже изображения, а на ПК счётчик вынесен к правому краю и кнопка шире. Подробности и исключения — в `RULES.md`.


**Категории услуг на телефоне:** не помещать все карточки принудительно в видимую ширину даже при 1–4 категориях. Эталон Эсмеральды — естественная ширина каждой карточки, 35 px высота, 15 px внутренние боковые отступы, 8 px между карточками, Manrope 12,705 px/500 (ещё на 10% крупнее предыдущей версии, на 21% крупнее оригинала Эсмеральды) и горизонтальная прокрутка. Начало первой категории остаётся на одной линии с первой карточкой услуги. Не путать этот блок с категориями полноэкранной галереи: их рамку/шрифт не менять.
